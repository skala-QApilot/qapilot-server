## 1. 서비스 개요

### 1.1 목적

NOVA Mobile은 무선 통신 서비스를 제공하는 사업자이며, **NOVA Self-Care**는 가입 고객이 영업점·콜센터를 거치지 않고 웹 채널에서 직접 회선·요금제·부가서비스·청구를 관리할 수 있도록 제공되는 셀프 서비스 채널이다. 본 서비스의 목적은 다음과 같다.

- 가입 신청부터 요금제 변경·해지까지의 전 라이프사이클을 비대면으로 처리한다.
- 요금제 변경을 즉시 또는 미래 일자 예약 형태로 제공해 고객 자율성을 확보한다.
- 사용량·청구·부가서비스 정보를 실시간 조회로 제공해 콜센터 인입을 절감한다.

### 1.2 제공 범위

| 구분 | 포함 | 제외 |
|------|------|------|
| 회선 | 무선 데이터·음성 단일 회선 | 결합 회선, 인터넷·IPTV, B2B 회선 |
| 가입 채널 | 웹 셀프케어 | 영업점, 콜센터, 모바일 앱 |
| 결제 | 청구·납부 정보 조회 | 실 결제 게이트웨이 연동 |
| 단말 | 단말 파손 보험 안내 | 단말 판매·할부, 보험 청구 접수 |
| 다국어 | 한국어 | 영어·기타 언어 |

### 1.3 용어 및 약어

| 용어 | 정의 |
|------|------|
| 고객 (Customer) | NOVA Mobile에 회원 등록된 개인 사용자 |
| 회선/오더 (Order) | 한 고객이 보유한 무선 가입 계약. 활성 상태(`CONFIRMED`)와 해지 상태(`CANCELLED`)를 가진다 |
| 요금제 (Plan) | 월 요금·데이터·음성·문자 제공량을 묶은 상품 단위. 별도 카탈로그 문서(`요금제정책.md`)로 관리 |
| 부가서비스 (Benefit) | 요금제에 부수되는 부가 혜택. 고객이 ON/OFF 토글로 선택 |
| 변경 예약 (Scheduled Change) | 미래 적용일을 지정한 요금제 변경 요청 |
| 청구 주기 (Billing Cycle) | 매월 1일~말일. 익월 25일 자동이체 청구 |
| 셀프케어 채널 | 본 문서가 정의하는 웹 셀프 서비스. 사용자가 직접 변경을 수행 |

## 2. 사용자 및 역할

### 2.1 주 사용자

| 사용자군 | 비중 | 주요 사용 시나리오 |
|----------|------|-------------------|
| 신규 가입 고객 | 25% | 요금제 카탈로그 비교 → 가입 신청 |
| 기존 가입 고객 (현행 유지) | 40% | 사용량·청구 조회, 공지 확인 |
| 기존 가입 고객 (변경 의향) | 30% | 요금제 변경 또는 변경 예약 |
| 해지 검토 고객 | 5% | 부가서비스 OFF, 해지 |

### 2.2 사용자 권한 모델

본 채널은 **고객 본인 계정만**의 자원에 접근한다. 모든 인증된 API는 서버측에서 `customer_id == 인증된 본인`을 강제하며, 타 고객 자원에 대한 요청은 존재 누설 방지를 위해 일관되게 `404 Not Found`로 응답한다. 관리자·상담사 권한은 본 채널의 범위 밖이며 별도 운영 콘솔에서 처리한다.

## 4. 기능 요구사항

### 4.1 인증 도메인

#### FR-AUTH-01 회원가입

| 항목 | 내용 |
|------|------|
| 화면 | `/signup` |
| 입력 | 이메일, 비밀번호(8~100자), 이름(1~100자), 생년월일, 보호자 동의 플래그(만 19세 미만 가입 시 필수) |
| 처리 | 이메일 형식 검증 → 중복 검사 → 비밀번호 bcrypt 해시 → 미성년자 여부 판정 → (미성년자) 보호자 동의 검증 → 고객 마스터 등록 |
| 성공 | 가입 완료 후 로그인 화면 이동 |
| 예외 | 이메일 중복 → "이미 등록된 이메일입니다", 형식 위반 → 입력 오류 표시, 미성년자 + 보호자 미동의 → "미성년자 가입 시 법정대리인의 동의가 필요합니다." |
| 정책 | 비밀번호 평문 저장 금지. 이메일은 시스템 전체 고유. 만 19세 미만 가입 시 법정대리인 동의(보호자 동의 플래그) 필수 (이용약관 v2.0 제5조 4항) |

#### FR-AUTH-02 로그인

| 항목 | 내용 |
|------|------|
| 화면 | `/login` |
| 입력 | 이메일, 비밀번호 |
| 처리 | 자격증명 검증 → JWT 발급(24시간) → 세션 이력 기록 |
| 성공 | `/dashboard` 진입 |
| 예외 | 자격증명 불일치 → "이메일 또는 비밀번호가 올바르지 않습니다" |
| 토큰 | 클라이언트 `localStorage`에 토큰·고객 프로필 저장 |

#### FR-AUTH-03 내 정보 조회

| 항목 | 내용 |
|------|------|
| 트리거 | 인증된 클라이언트가 본인 프로필 재조회 |
| 처리 | JWT 검증 → 고객 마스터에서 본인 row 반환 |
| 예외 | 토큰 누락·위조·만료 → 인증 실패 처리, 자동 로그아웃 |

### 4.2 요금제 카탈로그

#### FR-PLAN-01 요금제 목록 조회

| 항목 | 내용 |
|------|------|
| 화면 | `/plans` (인증 불필요) |
| 처리 | 활성 상태(`is_active=true`) 요금제만 ID 오름차순으로 노출 |
| 표시 | 요금제명, 월 요금(부가세 포함), 데이터 제공량, `is_minor_only=true`인 경우 "청소년 전용" 배지, 가입/변경 진입 버튼 |
| 정책 | 비활성 요금제는 목록에서 제외하며 직접 신청·변경 시 거부된다. **청소년 안심 요금제(`is_minor_only=true`)는 만 19세 미만 가입자만 신청 가능하며, 만 19세 이상 성인의 신청은 거부된다** (양방향 제한, 이용약관 v3.0 제13조의2 1·4항) |

#### FR-PLAN-02 요금제 상세 조회

| 항목 | 내용 |
|------|------|
| 화면 | `/plans/{id}` |
| 처리 | 단일 요금제의 가격·데이터·부가서비스 구성을 표시 |
| 예외 | 미존재 요금제 → 안내 후 카탈로그 복귀 |

### 4.3 가입 및 요금제 변경

본 도메인은 **신규 가입**, **즉시 변경**, **변경 예약**의 3개 흐름을 단일 화면(`/order/new?plan_id={id}`)에서 통합 제공한다. 화면은 고객의 현재 활성 요금제 보유 여부에 따라 모드를 자동 전환한다.

#### FR-ORDER-01 신규 가입

| 항목 | 내용 |
|------|------|
| 진입 조건 | 고객이 활성 요금제(`CONFIRMED`)를 보유하지 않은 상태 |
| 화면 | `/order/new?plan_id={id}` — 요금제 정보 + 약정 옵션 선택(NONE/12/24) + "가입 신청" 버튼 |
| 입력 | `plan_id`, `contract_type` (NONE/12/24, 기본값 NONE) |
| 처리 | 선택 요금제의 활성 상태 검증 → **청소년 안심 요금제 자격 검증**(만 19세 미만 가입자는 `is_minor_only=true`인 요금제만 허용) → 오더 생성(`CONFIRMED`, 월 요금 = 요금제 가격) → contract_type ≠ NONE 이면 `contracts-service`에 약정 생성 요청 |
| 성공 | 가입 완료 화면 + 내 오더 목록 진입 안내 |
| 예외 — 활성 요금제 보유 | "이미 구독 중인 요금제가 있습니다. 요금제 변경을 이용하세요." 안내 후 변경 모드로 전환 |
| 예외 — 비활성/미존재 요금제 | 요청 거부 |
| 예외 — 미성년자 + 일반 요금제 | "만 19세 미만 가입자는 청소년 안심 요금제만 신청할 수 있습니다." |
| 예외 — 성인 + 청소년 요금제 | "만 19세 이상 성인은 청소년 안심 요금제를 신청할 수 없습니다." (이용약관 v3.0 제13조의2 4항) |
| 예외 — contracts-service 호출 실패 | HTTP 502 "contracts-service 호출 실패". 본 버전에서는 보상 트랜잭션 미적용(오더는 생성되었으나 약정 누락 가능 — 본 결함은 결함 카드의 후속 PR에서 ground truth로 활용 예정) |
| 정책 | 회선당 활성 요금제 1건만 보유 가능. 동시 다회선은 본 채널에서 지원하지 않음. 청소년 안심 요금제(`is_minor_only=true`)는 만 19세 미만만 신청 가능하며 만 19세 이상 성인은 신청 불가 (양방향 제한, 이용약관 v3.0 제13조의2). 약정 옵션은 가입 시점에만 선택 가능하며 약정 시작·종료일은 KST 기준 (이용약관 v3.0 제13조의3) |

#### FR-ORDER-02 요금제 즉시 변경

| 항목 | 내용 |
|------|------|
| 진입 조건 | 고객이 활성 요금제를 보유한 상태에서 다른 요금제로 변경 시도 |
| 화면 | 동일 화면 `/order/new?plan_id={id}` — **변경 전/후 비교 카드** + 월 요금 차액·데이터 차액 요약 |
| 처리 | 청소년 안심 요금제 자격 검증(만 19세 미만 가입자는 `is_minor_only=true`인 요금제만 허용) → 기존 회선을 `CANCELLED` 상태로 전환 → 신규 요금제의 신규 회선(`CONFIRMED`)을 발급 → 신규 회선의 부가서비스 선택은 OFF 상태로 시작 → 기존 회선의 변경 예약이 있으면 동시 삭제 |
| 회선 식별자 | 변경 시점마다 신규 회선이 발급되므로 회선 식별자(`order_id`)는 갱신된다. 기존 회선은 이력으로 보존된다 |
| 성공 | 변경 완료 메시지 + 요금제 상세 진입 안내 |
| 예외 — 동일 요금제 | "이미 이용 중인 요금제입니다" 안내 |
| 예외 — 비활성/미존재 | 요청 거부 |
| 예외 — 비활성 오더 | 해지된 오더는 변경 불가 |
| 예외 — 미성년자 + 일반 요금제 | "만 19세 미만 가입자는 청소년 안심 요금제만 신청할 수 있습니다." (이용약관 v2.0 제13조의2) |
| 예외 — 성인 + 청소년 요금제 | "만 19세 이상 성인은 청소년 안심 요금제를 신청할 수 없습니다." (이용약관 v3.0 제13조의2 4항) |
| 약정 자동 동기화 | 즉시 변경 시 기존 회선의 활성 약정을 backend가 `PATCH /api/contracts/{old_order_id}/terminate` 로 호출하여 TERMINATED 상태로 전환한다. `is_upgrade` 플래그는 **backend가 자동 판정**한다(신규 plan.price ≥ 기존 plan.price이면 true). is_upgrade=true 시 위약금은 면제되어 0으로 산정된다 (이용약관 v3.0 제13조의4 5항). 신규 회선의 약정은 본 차수에서는 자동 생성되지 않으며(무약정으로 시작) 추후 차수에서 처리한다 |

| 예외 — 성인 + 청소년 요금제 | "만 19세 이상 성인은 청소년 안심 요금제를 신청할 수 없습니다." (이용약관 v3.0 제13조의2 4항) |

#### FR-ORDER-04 회선 해지

| 항목 | 내용 |
|------|------|
| 진입 | 오더 상세 화면 `/orders/{id}` — "해지하기" 버튼 |

| 예외 — 이미 해지 | "이미 해지된 오더입니다" |
| 정책 | 해지 후 동일 고객이 재가입을 원할 경우 신규 가입(FR-ORDER-01) 흐름을 사용한다 |

### 4.10 약정·위약금 (마이크로서비스 분리)

> **아키텍처 노트:** 본 도메인은 v3.0부터 별도 마이크로서비스 `contracts-service`(컨테이너 `minibss-contracts-service`, 포트 8001)로 분리되어 운영된다. backend(8000)는 가입 시 contracts-service에 HTTP POST를 송신하여 약정을 생성하고, frontend(3000)는 contracts-service에 직접 GET 호출하여 약정 정보·위약금 견적을 표시한다. JWT 시크릿은 backend와 contracts-service가 공유한다.

#### FR-CONTRACT-01 약정 조회

| 항목 | 내용 |
|------|------|
| 엔드포인트 | `GET /api/contracts/{order_id}` (contracts-service) |
| 처리 | 본인 오더 검증 → 약정 row 조회 |
| 응답 | `contract_type`, `monthly_discount`, `start_date`, `end_date`, `status` |
| 예외 — 미존재 | 404 "Contract not found" (오더는 있으나 약정이 등록되지 않은 경우 — 무약정 가입 시 의도된 상태) |
| 예외 — 권한 없음 | 403 "Order does not belong to current customer" |
| 정책 | 약정은 회선(오더)당 1건. 가입 시점에 한 번만 생성 (이용약관 v3.0 제13조의3 2항) |

#### FR-CONTRACT-02 위약금 견적

| 항목 | 내용 |
|------|------|
| 엔드포인트 | `GET /api/contracts/{order_id}/penalty` (contracts-service) |
| 처리 | 본인 오더 검증 → 약정 row 조회 → 현재 시점 기준 위약금 산정 |
| 산정 공식 | `위약금 = 사용 개월수 × 월 할인액` (이용약관 v3.0 제13조의4 1항) |
| 응답 | `months_used`, `monthly_discount`, `penalty_amount`, `as_of` |
| 정책 | 무약정(NONE) 또는 EXPIRED 상태 약정은 위약금 0. 본 차수에서는 견적 표시만 제공하며 자동 청구 통합은 범위 외 (이용약관 v3.0 제13조의4 4항) |

#### FR-CONTRACT-03 약정 해지 (서비스-투-서비스 호출)

| 항목 | 내용 |
|------|------|
| 엔드포인트 | `PATCH /api/contracts/{order_id}/terminate` (contracts-service) |
| 호출 주체 | backend의 `orders.cancel_order`, `orders.change_order_plan`, `orders._apply_due_scheduled_changes`. frontend는 직접 호출하지 않는다 |
| 입력 | `is_upgrade: bool` — **backend가 자동 판정**한 값. 신규 plan.price ≥ 기존 plan.price이면 true |
| 처리 | 본인 오더 검증 → 활성 약정 조회 → `status='TERMINATED'`로 전환 → 현재 시점 기준 위약금 산정. `is_upgrade=true`이면 산정된 위약금을 0으로 면제 (이용약관 v3.0 제13조의4 5항) |
| 응답 | `ContractPenaltyOut` (months_used, monthly_discount, penalty_amount, as_of). 면제된 경우 penalty_amount=0 |
| 예외 — 미존재 | 404 "Contract not found" (무약정 가입 또는 약정 미생성) — backend는 이를 무시하고 회선 변경/해지를 진행한다 |
| 예외 — 이미 종료 | 400 "Contract is not active" |
| 예외 — 권한 없음 | 403 |
| 정책 | 약정 종료 시 변경 흐름에 따라 자동 호출되며, 별도의 사용자 API 미노출. is_upgrade 판정은 서버 책임이며 클라이언트가 임의로 지정할 수 없다 (이용약관 v3.0 제13조의4 5항) |

### 4.9 자동 적용 처리 (시스템 동작)

요금제 변경 예약(FR-ORDER-03)은 **고객이 인증된 셀프케어 화면에 진입할 때마다** 시스템이 다음을 자동 수행한다.

1. 본 고객의 변경 예약 중 적용일이 오늘 이하인 항목을 조회한다.
2. 각 예약에 대해 신규 요금제가 활성 상태이고 회선이 활성인 경우에 한해:
   - 기존 회선을 `CANCELLED` 상태로 전환한다.
   - 신규 요금제의 신규 회선을 `CONFIRMED` 상태로 발급한다.
   - 신규 회선의 부가서비스 선택은 OFF 상태로 시작한다.
3. 신규 요금제가 비활성이거나 회선이 해지된 경우 예약은 적용 없이 폐기된다.
4. 처리된 예약은 삭제된다.

본 처리는 화면 진입(대시보드, 오더 목록, 사용량, 청구 등) 어디서든 트리거되며, 별도의 배치 스케줄러를 두지 않는 **요청 구동 자동 적용** 방식이다. 고객이 장기간 미접속한 경우에도 다음 접속 시점에 일괄 반영된다.

## 5. 비즈니스 규칙 요약

| ID | 규칙 |
|----|------|
| BR-01 | 한 고객은 동시에 활성(`CONFIRMED`) 회선을 최대 1건 보유한다. |
| BR-02 | 회선 1건은 단일 요금제로 구성되며 수량(qty)은 1로 고정된다. |
| BR-03 | 활성 회선이 있는 고객의 신규 가입 요청은 거부되며 변경 흐름으로 안내된다. |
| BR-04 | 동일 요금제로의 변경 또는 변경 예약은 거부된다. |
| BR-05 | 변경 예약의 적용일은 오늘 이후만 허용된다. |
| BR-06 | 회선당 활성 변경 예약은 최대 1건이며, 신규 예약은 기존 예약을 덮어쓴다. |
| BR-07 | 요금제 즉시 변경 또는 예약 자동 적용 시 기존 회선이 해지(`CANCELLED`)되고 신규 회선이 발급(`CONFIRMED`)되며, 신규 회선의 부가서비스 선택은 OFF 상태로 시작한다. |
| BR-08 | 회선 해지 시 해당 회선의 활성 변경 예약은 동시 삭제된다. 사용자 의도 해지와 변경 흐름으로 인한 자동 해지에 동일하게 적용된다. |
| BR-09 | 비활성 요금제(`is_active=false`)는 신규 가입·변경·예약 대상에서 제외된다. |
| BR-10 | 부가서비스 토글은 활성 회선이며 회선의 현재 요금제 카탈로그에 매칭된 부가서비스에 한한다. 해지 회선의 부가서비스 변경 또는 미매칭 부가서비스 토글은 거부된다. |
| BR-11 | 비밀번호는 bcrypt 해시로 저장하며 평문 저장·로그 출력은 금지된다. |
| BR-12 | 본인 외 고객의 회선·예약·부가서비스에 대한 접근은 일관되게 미존재(`404`)로 응답한다. |

### 8.2 표준 응답 규약

- 모든 응답은 JSON. 성공은 `200`/`201`, 검증 실패는 `422`, 비즈니스 규칙 위반은 `400`/`409`, 인증 실패는 `401`, 미존재 또는 인가 격리는 `404`로 통일한다.
- 모든 응답에 `X-Trace-Id` 헤더를 부여한다.
- 비즈니스 메시지는 한국어로 응답한다(예: "이미 구독 중인 요금제가 있습니다").

## 10. 운영 요구사항

| 항목 | 내용 |
|------|------|
| 환경 분리 | 개발·스테이징·운영의 3 단계. 모든 환경 변수는 외부화하며 코드에 자격증명 하드코딩 금지 |
| 배포 단위 | 컨테이너 이미지(백엔드, 프론트엔드 정적 산출물). DB는 매니지드 또는 별도 인프라 |
| 데이터베이스 | 운영은 매니지드 PostgreSQL 15. 개발/스테이징은 컨테이너 내장 가능 |
| 로깅 | uvicorn 표준 로그 + 트레이스 ID 결합 JSON 로그(향후 확장) |
| 백업 | 운영 DB는 일 1회 스냅샷, 7일 보존 |
| 모니터링 | API 응답시간·에러율, DB 커넥션·CPU·디스크 |
| 시크릿 관리 | JWT 비밀키·DB 자격증명은 시크릿 매니저 또는 K8s Secret으로 주입 |

## 11. 변경 관리

### 11.1 변경 절차

1. 신규/변경 요구사항은 본 문서 또는 `요금제정책.md`에 PR로 제안한다.
2. 셀프케어 파트가 영향 분석을 수행하고, 필요 시 정보보호팀·CRM 데이터팀에 협의 단계를 거친다.
3. PM 승인 후 main 브랜치에 머지한다. 본 문서 상단 개정 이력 표에 row를 추가하고 버전 번호(semver)를 증가시킨다.
4. 데이터베이스 스키마 변경이 수반되는 경우 동일 PR에 Alembic 마이그레이션 파일을 포함한다.
5. 요금제·부가서비스 카탈로그 변경(가격·코드·구성)이 발생하는 경우 시드 스크립트도 동일 PR에서 갱신한다.
